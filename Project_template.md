|           Характеристика           | **Локальные Sentence Transformers**                                                                                                                                                                                                                                                | **Облачные OpenAI Embeddings**                                                                                                                                                                                                                                           |

**Решение:** Для выполнения задания выбрана локальные Sentence Transformers. Для кейса компании лучше использовать облачное решение, если нет требований к безопасности.

## 1.3 Сравнение векторных баз ChromaDB и FAISS

Сравните векторные базы ChromaDB и FAISS:
- скорость поиска и индексации
- сложность внедрения и поддержки
- удобство в работе
- стоимость владения (учёт инфраструктуры)

|              Характеристика              | **ChromaDB**                                                                                                                                                  | **FAISS**                                                                                                                                                   | 
|:----------------------------------------:|:--------------------------------------------------------------------------------------------------------------------------------------------------------------|:------------------------------------------------------------------------------------------------------------------------------------------------------------|
|       Скорость поиска и индексации       | Оптимизирована для малых и средних нагрузок. На больших масштабах (10M+ векторов) начинает уступать из-за накладных расходов БД. Индексация автоматизирована. | Самое быстрое решение на рынке. Поддерживает GPU-ускорение, что позволяет индексировать и искать по миллиардам векторов кратно быстрее Chroma.              |
|     Сложность внедрения и поддержки      | Установка в одну строку, минимальная конфигурация. Не требует глубоких знаний алгоритмов поиска. Поддержка заключается в обновлении Docker-контейнера.        | Это библиотека, а не сервер. Нужно самостоятельно писать код для сохранения индексов, управления конкурентным доступом и распределения нагрузки.            |
|            Удобство в работе             | «Все в одном»: хранит векторы, метаданные и сам текст документа. Есть встроенная фильтрация по метаданным и простая интеграция с LangChain/LlamaIndex.        | Работает только с числами (ID векторов). Для хранения текста и метаданных нужно подключать внешнюю БД (например, PostgreSQL) и синхронизировать их вручную. |
| Стоимость владения (учёт инфраструктуры) | Потребляет больше RAM для управления индексами и метаданными. Требует меньше затрат на инженеров-разработчиков за счет простоты.                              | Позволяет сильно сжимать индексы (квантование), экономя на памяти, но требует дорогих специалистов для настройки и поддержки.                               |

**Вывод:** Если требует гибкости и быстрой разработки — данные по ChromaDB точны. Если же вы строите систему уровня "поиск по всему интернету" — данные по FAISS подчеркивают его лидерство в производительности при высокой сложности поддержки.

**Решение:** Для выполнения задания выбрана ChromaDB. Для кейса компании так же следует использовать ChromaDB, т.к FAISS не работает с метаданными, что не совсем подходит для приведенного кейса.

## Как использовать
1. Запуск
docker-compose up -d chromadb

2. Создание индекса (с отчетом о времени)
docker-compose run --rm indexer python build_index.py

3. Проверка системы
docker-compose run --rm indexer python query_index.py stats

4. Поиск
docker-compose run --rm indexer python query_index.py "у кого были драконы?"

5. Интерактивный режим
docker-compose run -it --rm indexer python query_index.py
